# Verification boundary

Run `./tests/host/run.ps1 -RunId <own-run> -Label <fresh-label>` from the repository. The runner prepares a synthetic TLS fixture and original font input inside that run, reads the integrated backend directly, verifies pinned Node/Playwright/font inputs and hashes executed sources before/after tests. It creates no trust-store entry and makes no real provider calls. All fixtures needed to rerun are retained in the repository.

Node 24.19.0; Playwright 1.63.0; Chromium 153.0.8010.12 revision 1243, Firefox 155.0 revision 1543, WebKit 26.6 revision 2359. Pinned existing toolchain is read-only. Main browser binaries, package metadata/lock and entry points are hashed; this is not a whole-machine/DLL supply-chain qualification. Profiles, APPDATA/LOCALAPPDATA overrides, downloads and artifacts are inside the run.

Frozen host-v1 fixture records exact public bytes/hash/MIME/routes and semantic expectations. Worker executes a synthetic WASM module returning 42, tests SharedArrayBuffer and worker fetch; font is the unchanged OFL Patrick Hand pinned to the repository's Google Fonts commit. This is **not the production geometry/engine/font catalogue test**. Test HTML/JS/CSS/WASM is authored for this task. Synthetic TLS is generated with .NET without a certificate-store install; TLS key remains a private test input, excluded from production handoff. Each certificate is intentionally random, valid seven days, and separately fingerprinted. Regeneration for later reruns creates a new fixture/evidence generation; never silently use it as the frozen original.

HTTPS protocol tests use explicit synthetic CA trust. Browser tests ignore certificate errors solely for that synthetic certificate; real hostname/chain/public trust is unqualified. HTTP integration servers bind loopback with OS-assigned ports. CLI tests first obtain OS-assigned free ports and then reopen them explicitly, so another process stealing the port causes a test failure rather than a fallback deployment. Synthetic local IdP uses real one-use code/PKCE/RS256/nonce/state verification in the unchanged backend. Its authorization and token/JWKS endpoints are local HTTP allowed only by the backend test harness. Production host CLI exposes no testOnly/auth bypass.

Browser tests prove COI on navigation/reload and in Dedicated Worker, WASM execution, font load, blocked eval/inline script, real top-level IdP redirect, HttpOnly cookies, CSRF rejection, logout, no API/auth CacheStorage entries, and public-shell retrieval with COI when the actual HTTPS host is stopped. API fails with a network error then. Backend owner + two members are separately exercised over HTTPS, including isolation and immediate suspension.

Initial iterations are retained in evidence. Replacing API fetch interception with a complete SW bypass fixed callback handling. Browser request events under SW can expose a final response instead of a redirect; browser tests observe actual host 303 records and final authenticated behavior, while the separate HTTPS protocol test checks exact callback headers. Playwright offline emulation produced Firefox NS_ERROR_OFFLINE/WebKit internal reload failures in that iteration. Final offline evidence uses an actual stopped HTTPS host, **not airplane mode/network adapter disconnect or those emulation APIs**. Those device/browser offline transitions remain unverified.

Generated SW source is also exercised under a controlled JS runtime against redirects/final-login-200/private/error responses, mixed build/MIME/COI/hash, oversize streams, poisoned CacheStorage, and API/query/Authorization bypass. This does not claim resistance to malicious same-origin application JavaScript with independent CacheStorage/DOM access. Such code is inside the trusted build boundary. Production input-SVG sanitization and private offline storage/lease belong to frontend integration.

CLI tests execute actual host/backend CLIs, exclusive lock rejection, protected HTTP, stopped-writer backup, fresh-directory SQLite restore with AI hold and session revocation policy, and static manifest rollback. The seeded CLI backup does not contain production user data. Graceful child stop is invoked through a test-only process-control wrapper which emits SIGTERM in that child; no stop-file endpoint or environment bypass exists in production modules. Abrupt OS termination and stale-lock operational recovery are documented, not qualified.

Open limitations: actual frontend CSP compatibility, complete engine/catalog/schema cache generations and lease migration, real host/IdP/MFA/conditional-access, certificate issuance/renewal/public trust, platform outside this Windows host, login flood/load/RSS saturation, process ACL/firewall/log rotation, CDN/proxy configurations, offsite backup/key recovery, production restore/reconciliation, measured RPO/RTO/SLA. Static SVG/XML, Range, compression, streaming uploads/SSE/WebSockets and arbitrary origins are explicitly unsupported in host v1. No production AI call, charge, deployment, OIDC registration or agent/review seat was launched.

This is implementation and self-testing. Caller requested inherited GPT-6 Astra / max. Runtime model/effort is not independently evidenced; service-tier/fast controls are unavailable. No claim that seat-config review settings were achieved. Parent's independent review remains necessary.
