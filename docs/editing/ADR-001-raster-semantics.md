# ADR-001: deterministic raster editing v1

Status: implemented candidate, 2026-09-08. This is implementation evidence, not an independent seat review. The delegated session inherited Astra/max; fast mode was not exposed or verified. No child agents were used.

The seven tools operate on bounded, trusted, straight-alpha, 8-bit sRGB RGBA. They use original ECMAScript algorithms and typed arrays, with Web Crypto SHA-256. There are no runtime dependencies, geometry parsers, polygon booleans, triangulators, DOM rendering, raw SVG execution, file access, or network calls in the pixel core. The optional Worker adapter uses only messages. Choosing JS for this isolated pixel processor does not replace the parent's Rust/WASM manufacturing kernel.

## Sampling and coordinates

An image is the rectangle [0,width) × [0,height), origin top left, y increasing down. Pixel (x,y) is sampled at (x+0.5,y+0.5). Gesture positions are rounded to 1/256 px, ties to even, once during normalization. Coordinates outside the image are allowed up to absolute 100,000. Strokes are evaluated against original endpoints with bounded image iteration; endpoints are not clamped into unwanted edge strokes. Flood seeds use floor and outside seeds select nothing.

Brush width is a diameter in image pixels, 1–60 including fractional widths. Missing pressure means 1×; explicit pressure p in [0,1] means 0.4+1.2p times width. This reaches 96 px effective width at maximum pressure. The renderer must distinguish missing pressure from an explicit zero. Round brushes sweep linearly varying discs; square brushes sweep axis-aligned, linearly varying squares. Boundary inclusion is inclusive. Every segment contributes to one binary union mask for the complete gesture. Crossings, backtracking, and duplicate points do not apply alpha repeatedly. Different gestures do composite again. No antialiasing, noise removal, minimum island size, simplification by area, or implicit smoothing is applied.

Shift direction uses the closest orthogonal projection onto horizontal, positive diagonal, vertical, or negative diagonal, in that tie order. Each segment anchors to the previous snapped point. Width is unaffected by zoom. The affine helpers use [a,b,c,d,e,f] with x'=ax+cy+e, y'=bx+dy+f. The renderer includes CSS offsets, pan, zoom, and DPR consistently; inverse mapping returns unclipped continuous image coordinates. Project calibration and device input stay with the parent/Opus.

## Tool behavior

| Tool | Exact selected pixels and operation |
| --- | --- |
| paint | Flood from one or more seeds, four-connected by default (eight optional). Match all RGBA channels within explicit max-channel tolerance of that seed; tolerance defaults to 0 and is not transitive. All fully transparent pixels match regardless of hidden RGB. Replace selected RGBA with selected color by default; source-over is optional. This recolors the selected region, rather than interpreting B as a freehand brush. Selecting the exterior background is explicit and does not select enclosed transparent holes. |
| line | Polyline through supplied points with round caps and round or square brush, default round. A single point is a dab. Source-over by default; replace optional. A normal drag sends two points; more points express the renderer's sampled path. |
| curve | Uniform Catmull-Rom interpolation through clicked knots, duplicated endpoint convention. Convert each span to cubic Bézier controls and subdivide with de Casteljau until both controls are within 1/8 px of the segment, at most depth 16 / 16,384 segments. Pressure scale interpolates in span parameter. Fewer than three points use line/dab. Uniform interpolation can overshoot near corners or duplicate knots. This is a specified pixel curve, not a source geometry parser or a manufacturing tolerance. |
| erase | Same stroke selection. Default hole mode attenuates destination alpha; full opacity clears selected RGBA to zero. Merge mode recolors only already occupied pixels and preserves their alpha. |
| cut | Same explicit stroke/mode policy as erase. Its normal drag makes a width-bearing slit; at full opacity this can split occupied regions into islands. It does not automatically close or fill a path. |
| crop | Rectangular or elliptical shape, keep inside by default or keep outside. The discarded side receives the shared hole/merge operation. Rectangle edges are min-inclusive/max-exclusive; ellipse boundary is inclusive. Drag endpoints may be reversed. Shift square/circle uses the larger absolute drag extent anchored to start. A zero-area drag is a no-op. **Canvas dimensions and coordinate origin remain unchanged**: this crop is a selection mask, not a bitmap resize. |
| heal | Default region mode selects four-connected, exactly transparent components. Auto color is selected independently from each component's occupied boundary; explicit color is also supported. A component touching an image edge needs allowExterior=true or a bounded brush selection. Brush mode fills transparent pixels in its stroke only. Occupied accents are never removed. All-gaps mode below fills runs under an explicit width threshold. |

Erase, cut, and crop share mode=hole|merge, opacity, and explicit/auto merge color. At merge opacity 255 selected RGB is replaced; intermediate opacity interpolates RGB while keeping destination alpha. Explicit merge colors must be opaque. Auto merge/heal counts cardinal boundary edges to occupied, unselected pixels for each connected selected component. Most frequent full RGBA wins; ties choose the smallest unsigned big-endian RGBA key (R, then G, B, A ascending). Transparent boundary neighbors do not vote. No occupied boundary yields NO_BOUNDARY_COLOR and no commit; selecting a color resolves it.

For all-gaps, scan horizontal and vertical transparent runs in the **unchanged input**. A run qualifies only when both endpoints are occupied and its length is 1..maxGapPx. Fill each qualifying pixel from its closest endpoint; equal distances use the same lexicographic RGBA tie. If both orientations qualify, use the shorter endpoint distance, then color tie. Explicit color overrides auto color. This can bridge intentional spaces between separate objects, so the parent can display prepare's provisional image before commit. It never erodes pixels or silently deletes small features. Transparency means alpha=0, not a guessed near-transparent threshold.

All-gaps requires maxGapPx and pixelSizeMm (isotropic image scale). Its design threshold is maxGapPx × pixelSizeMm, saved in the command. gapFromDesign converts a desired mm maximum to a whole-pixel threshold with floor; a four-ULP neighborhood of an integer quotient counts as equality to avoid 0.3/0.1 becoming 2. The resolved value must be displayed. Anisotropic calibrated inputs need an explicit adapter decision; do not derive thresholds from screen zoom.

## Color and alpha

Selected colors are integer RGB or RGBA (omitted alpha=255); opacity is an integer 0..255. Opacity 0 is a no-op for every tool. Nonzero replace sets color with alpha=roundEven(colorAlpha×opacity/255). Source-over computes straight-alpha channels directly in **encoded sRGB byte space**, not linear-light blending. Effective source alpha is rounded first; final RGB and alpha use integer-ratio ties-to-even. Destination hidden RGB contributes zero when destination alpha is zero. Zero effective source alpha leaves all destination bytes untouched. Explicit clearing or replacement to transparent canonicalizes selected RGBA to [0,0,0,0]. Bytes outside selection, including hidden RGB, are preserved.

No decoder, EXIF correction, sRGB conversion, resampling, material palette quantization, vectorization, or gradient simplification happens here. The adapter must validate and produce the bounded derivative separately. A confirmed vector/source-to-raster conversion must preserve the original source and its metadata and record resolution/conversion choices. Partial alpha and source-over may introduce additional colors. Converting this appearance to discrete printing materials is a separate explicit, versioned, previewed operation.

Binary coverage and 1/8 px curve flattening can change boundary samples. A working raster at, for example, 45 mm / 520 px has about 0.0865 mm pixel pitch; this does not demonstrate micron geometry, shared manufacturing seams, meshing, printability, or fit. Existing one-pixel accents and holes survive unless the selected operation targets them.

## Transactions, ownership, and history

createEditor copies source metadata and RGBA synchronously before its first await. original() returns a copy of that initial bounded raster. It is the immutable **pre-edit raster derivative**, not a substitute for full-resolution original file bytes. The supplied source hash identifies bytes owned and verified by the parent source store; the editor never opens those bytes.

The working image and initial raster each have a SHA-256. Hash domain is 24 bytes: ASCII ARCH-RGBA-v1 at bytes 0..11, zero padding to 16, little-endian uint32 width at 16 and height at 20, followed by exact RGBA bytes. Hash includes alpha and hidden RGB. Tokens include source ID, original source hash, original raster hash, working hash, and monotonic revision. Undo/redo increment revision even when content returns to an earlier hash, preventing stale ABA reuse.

prepare snapshots a normalized serializable command, works privately, returns an explicitly provisional image, exact changed bounds/count, and encoded undo byte count. It does not modify the committed image or publish history. A caller may inspect/cancel this preview and check history budget. commit requires the controller's **current** token, rechecks it and cancellation, then synchronously swaps image/hash/revision without user callbacks or awaits. A changed gesture returns exactly one undo payload; an unchanged gesture returns undo=null and keeps revision. Public image buffers never alias internal state.

One operation runs at once; at most one preparation is retained. Commit/cancel it before preparing another. Replay may run with a retained preparation, making that preparation stale. Busy, invalid, cancelled, over-budget, and conflicting work retains the last image. Cancellation works at progress checkpoints or after preparation. The parent must still discard source/revision-stale Worker responses, and terminate an unresponsive Worker as its watchdog policy; init another Worker when changing the source.

apply is a convenience for a caller whose editor owns the authoritative token. For project integration use prepare/commit and supply the live controller token. Revision here is source-editor state; other project mutations remain subject to the parent's project-wide revision check. A CPU commit is not a storage acknowledgment. The controller owns durable journaling, reload reconstruction, source assets, final undo/redo stacks and the 20-transaction/24-MiB budget policy. No history trimming or hidden persistence is performed here.

Undo contains the minimal changed rectangle, exact changed pixel count, before/after RGBA rectangle buffers, source/revision/hash provenance, and the normalized gesture. The rectangle may include unchanged interior pixels; this keeps encoding predictable. encodeUndo uses a bounded binary frame (ARCHED1 + NUL, little-endian metadata and patch lengths, zero reserved field, UTF-8 JSON metadata, before bytes, after bytes). decode validates framing and schema. Replay verifies current content, exact bounds/count, old patch bytes, and target SHA-256 before commit. The parent must content-hash the full encoded payload when persisting it; the image hash is not an authentication signature for command metadata.

## Work and memory policy

Hard limits: 1280 px per edge / 1,638,400 pixels; 4,096 stroke points; 256 region seeds; 16,384 curve segments; 65,536 distinct colors in one automatic boundary vote; gap 1–60 px; depth 16; 1 MiB encoded metadata; 100,000,000 accounted work units per job. Controls may lower work/checkpoint limits, never increase them. A budget failure rejects the operation atomically.

A work unit counts bounded pixel/neighbor/segment processing as specified in the loops; it is not a microsecond or an instruction counter. The default scheduler yields a Worker task after about 8,192 units (a loop can overshoot by at most a bounded row/chunk), emits phase and cumulative work, and checks cancellation again. No Atomics.wait, blocking join, or main-thread waits exist. Web Crypto's single bounded digest and bounded typed-array allocations/copies are not interruptible, but their results are checked before publication. Custom microtask-only scheduling is for deterministic tests, not production cancellation.

The conservative per-editor allocation estimate is 64×pixels + 96×maxBoundaryColors + 1 MiB, gated at 128 MiB (112,197,632 bytes at maximum dimensions). It bounds intended typed buffers plus estimated object overhead, not browser process RSS or a VM allocator guarantee. A 1280² image is 6,553,600 RGBA bytes; a full changed rectangle has 13,107,200 patch bytes plus metadata/header. Returned previews/results/payloads are caller-owned; retained caller copies, RPC ingress copies, and history are additional and must be budgeted by the controller. Use transfer lists and release old previews. The host should bound incoming requests before Worker structured cloning and maintain one outstanding operation.
