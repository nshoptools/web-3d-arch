# Application build API (implementation, 2026-09-08)

The builder compiles the captured actual index.html -> src/main.mjs ->
src/integration/product-entry.mjs. No source/controller/core/UI modifications.
It does not qualify the running app or invent a native-ready proof.

Proposed commands after integration (all absolute paths, repository-contained):

~~~text
node tools/application/cli.mjs prepare <application-input.json> <new-build-directory>
node tools/application/cli.mjs package <prepared-build-directory> <new-release-directory>
node tools/application/cli.mjs verify <prepared-build-directory>
~~~

PowerShell tools/application/run.ps1 dot-sources project-env.ps1 with explicit
Seat/RunId, then dispatches. No default module pair or default tmp module path.
The input declares sourceRoot, app toolchain root, printing toolchain root,
module and wasm paths/bytes/SHA256, library root + all five document pins,
and license provenance. The engine contract is explicitly ABI2/semantics3/source2.

prepare freezes the permitted source set, original pair, runtime RUNTIME_FILES
schema5, licenses and tooling pins BEFORE compilation. Vite8.2.2 is read-only;
configFile/envFile/publicDir disabled, no source maps or asset inlining, Workers
use ES modules. A build plugin records the actual module/resource graph. Bare
packages resolve only to pinned, explicit read-only toolchain roots. Node backend,
test/fixture entries, source-provider secrets, .env, credentials and user.keys
are never public bundle inputs.

The ONLY engine rewrite replaces EXACTLY TWO quoted arch-kernel.wasm literals
with arch-kernel.<full wasm SHA256>.wasm. Original pair stays in inputs. Receipt
records original wrapper SHA, two replacements, derived wrapper SHA and names
arch-kernel.<full derived wrapper SHA256>.mjs / arch-kernel.<full wasm SHA256>.wasm.
All Vite output bytes stay unchanged with cache revalidate; engine files and
library configs/resources use full SHA URLs. No recursive emitted-JS rewriting.

Outputs include actual Vite manifest + collected graph, frontend file/hash pins,
explicit Worker/new-URL references, runtime-lock.json, license pins, package-input.json
for tools/release/plan.mjs and build.mjs, and an input-stability/derivation receipt.
release-bindings.json is generated by the existing release plan with the actual
compiled entry URL and original library plus separate transport binding.

verify rereads captured and live pins, compiled outputs, original/derived module
pair and exact file set. package requires this check before calling the existing
plan/build. Source changes fail closed before publication and require a new capture.
Failures retain evidence only; no partial artifact is labeled ready.

Library may be supplied from any explicitly named read-only repository directory.
All original config hashes must match current supplied sourceRoot files; ready must
cover 21,391 original resources + four configs, with 7,751 PNG previews. Frozen
materializer receives unchanged catalog/deployment; separate source-transport
helper is bundled into actual release bootstrap. Config limit64MiB each.

Parent owns production entry/bootstrap/engine integrity wiring and final combined
native pair. Compiled-entry smoke is package plumbing evidence, not full app,
target fit, slicer qualification, deployment, or independent review.
